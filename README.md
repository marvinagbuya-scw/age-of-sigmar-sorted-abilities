# Age of Sigmar — Sorted Abilities

Displays Age of Sigmar 4th edition ability cards grouped into the phases they're
used in, designed to be printed and used at the table.

No backend — all ability data lives in JSON files under `public/data`.

## Getting started

```bash
npm install
npm start              # dev server on http://localhost:4200
npm run storybook      # component previews on http://localhost:6006
npm test               # validates the data, then runs unit tests
npm run validate:data  # data checks on their own
npm run build          # production build
```

## Printing

Open the list and hit **Print list** (or Ctrl+P). The stylesheet targets A4
portrait: cards lay out two-up, a card never splits across a page break, phase
headings never get orphaned at the foot of a page, and the phase colours are
forced through with `print-color-adjust` since browsers strip backgrounds by
default.

## How sorting works

Two separate concepts, deliberately decoupled:

- **Phase** decides _which section_ a card is printed in, following the turn
  sequence: deployment → start of battle round → hero → movement → shooting →
  charge → combat → end of turn → end of battle round → passive.
- **Band** decides _what colour_ the card is. Several phases share a band.

| Phase                                            | Band         | Colour |
| ------------------------------------------------ | ------------ | ------ |
| `deployment`, `passive`, `start-of-battle-round` | `deployment` | black  |
| `hero`                                           | `hero`       | gold   |
| `movement`                                       | `movement`   | grey   |
| `shooting`                                       | `shooting`   | teal   |
| `charge`                                         | `charge`     | orange |
| `combat`                                         | `combat`     | red    |
| `end-of-turn`, `end-of-battle-round`             | `end`        | purple |
| _any phase, when `reaction` is set_              | `reaction`   | green  |

A reaction keeps the phase it triggers in — so a reaction to a Fight ability is
printed in the **Combat Phase** section — but wears the green band. This means
everything you need for a phase is in one place while you're playing.

Within a phase, cards sort by: whose turn (your → any → enemy), then
non-reactions before reactions, then source (faction-wide first, warscroll
last), then name.

Colours live as `--aos-*` custom properties in `src/styles.scss`. The band
classes are generated by a loop in `src/styles/_bands.scss` — add a band in one
place, not eight.

## Adding ability data

Data lives in `public/data/<faction-id>.json`. Run `npm run validate:data` after
editing; it fails on unknown phases, duplicate ids, broken back-references and
missing effect text.

> **The bundled Soulblight Gravelords data is sample data.** Every ability is
> flagged `"sample": true` and was written to exercise the layout, not
> transcribed from the rules. Values and wording are not accurate. Replace them
> with the real text and drop the flag — the in-app warning banner disappears
> once no ability is flagged.

### File shape

```jsonc
{
  "id": "soulblight-gravelords",
  "name": "Soulblight Gravelords",

  "factionAbilities": [], // always apply, no army selection needed
  "battleFormations": [], // { id, name, abilities: [] }
  "heroicTraits": [], // one ability per trait
  "artefactsOfPower": [], // one ability per artefact
  "spellLores": [], // { id, name, abilities: [] }
  "manifestationLores": [], // { id, name, abilities: [] }
  "units": [], // { id, name, keywords: [], abilities: [] }
}
```

An empty section is a known gap, not an error.

### Ability shape

```jsonc
{
  "id": "sbgl-the-hunger", // unique across the file
  "name": "The Hunger",
  "timing": {
    "phase": "combat", // decides the printed section
    "turn": "your", // "your" | "any" | "enemy" — optional
    "reaction": "You declared a Fight ability for this unit", // optional; forces the green band
    "frequency": "once-per-battle", // "once-per-battle" | "once-per-turn" | "once-per-turn-army"
  },
  "declare": "Pick a friendly unit that has fought this phase.", // omit for passives
  "effect": "Heal (1) that unit.", // required
  "keywords": ["Core", "Heal"], // use [] if none
  "castingValue": 7, // Spell only
  "chantingValue": 4, // Prayer only
  "usedBy": "Friendly SOULBLIGHT GRAVELORDS units", // optional
  "source": { "kind": "faction" },
  "sample": true, // remove once verified against the rules
}
```

### `source` must match its section

The validator enforces this, so a copy-paste slip gets caught rather than
silently breaking army filtering later.

| Section                          | `source`                                                                |
| -------------------------------- | ----------------------------------------------------------------------- |
| `factionAbilities`               | `{ "kind": "faction" }`                                                 |
| `battleFormations[].abilities`   | `{ "kind": "battle-formation", "formationId": "<the formation's id>" }` |
| `heroicTraits`                   | `{ "kind": "heroic-trait" }`                                            |
| `artefactsOfPower`               | `{ "kind": "artefact-of-power" }`                                       |
| `spellLores[].abilities`         | `{ "kind": "spell-lore", "loreId": "<the lore's id>" }`                 |
| `manifestationLores[].abilities` | `{ "kind": "manifestation-lore", "loreId": "<the lore's id>" }`         |
| `units[].abilities`              | `{ "kind": "warscroll", "unitId": "<the unit's id>" }`                  |

### Adding a warscroll

```jsonc
{
  "id": "sbgl-vampire-lord",
  "name": "Vampire Lord",
  "keywords": ["HERO", "WIZARD (1)", "INFANTRY", "VAMPIRE"],
  "abilities": [
    {
      "id": "sbgl-vl-supernatural-strength",
      "name": "Supernatural Strength",
      "timing": { "phase": "combat", "turn": "any" },
      "declare": "Pick a friendly SUMMONABLE unit wholly within 12\" of this unit.",
      "effect": "Add 1 to the Attacks characteristic of that unit's melee weapons.",
      "keywords": ["Once Per Turn"],
      "source": { "kind": "warscroll", "unitId": "sbgl-vampire-lord" },
    },
  ],
}
```

## Project layout

```
public/data/                 faction JSON
scripts/validate-data.mts    data validation (imports the app's own enums)
src/styles.scss              --aos-* palette, resets, @page print rules
src/styles/_bands.scss       band list + mixins that generate the colour classes
src/app/core/models/         Ability, Timing/Phase/Band, ArmyList, grouping
src/app/core/services/       data loading, army selection
src/app/ability-card/        the card component + Storybook stories
src/app/ability-list/        phase-grouped list and print layout
```

## Not built yet

Army-list filtering. The model and `SelectionService` are in place —
`isUnlocked` already decides whether an ability applies to a given army, and
faction/formation/lore abilities always pass — but there's no picker UI, so the
full faction list renders. Adding the UI is additive; no rework needed.

## Notes for future work

- Storybook needs two things that aren't obvious. `.storybook/main.ts` sets
  `css.preprocessorOptions.scss.loadPaths` because Vite doesn't inherit
  `stylePreprocessorOptions` from `angular.json`, and `.storybook/preview.ts`
  imports `src/styles.scss` because the Angular builder doesn't inject global
  styles into the preview iframe. Remove either and cards render unstyled.
- White on the gold `--aos-hero` band is about 3.3:1 contrast, which passes only
  because header text is bold. Don't shrink it.
